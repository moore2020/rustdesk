# 多 ID / 中继服务器选择设计

## 意图

RustDesk 当前通过一套全局 ID/中继服务器配置建立远程连接。用户需要在使用不同组织或个人的 rendezvous/relay 服务时进入“设置 → 网络”手动替换配置，再切回原配置。

本功能让桌面端用户维护多个服务器档案，并在新建远程连接时选择本次连接使用的档案；同一个远程设备记住上一次成功连接所用的档案，从而不再反复修改全局设置。

## 目标

- 仅支持 Flutter 桌面端：Windows、macOS、Linux。
- 在“设置 → 网络”维护多个服务器档案。
- 新建连接页面使用 A 方案：在远程 ID 输入区域附近增加 ID/Relay Server 下拉选择。
- 每个远程设备 ID 保存最近一次成功连接使用的服务器档案。
- 远程桌面、文件传输、终端、端口转发、RDP、查看摄像头等同一远程 ID 的连接类型共享同一服务器选择；这些功能不增加各自的服务器选择控件。
- 连接失败、取消、尚未建立连接时不更新设备偏好。
- 已建立的会话不受之后切换或编辑服务器档案影响。
- 首次升级时保留既有单服务器配置和既有连接行为。

## 非目标

- 第一版不修改 Android、iOS 或 Flutter Web。
- 不修改外部 URI、命令行参数和现有 `id@server` 连接语法。
- 不在远程会话工具栏中增加服务器切换；服务器选择只发生在新建连接页。
- 不让服务器下拉选择临时改写全局 Rust `Config`。
- 不改变服务器连通性测试、API 登录或既有单服务器配置的语义；迁移后的全局默认档案继续作为未指定档案的全局行为来源。
- 不把 API Server 或 Key 拆成独立的全局配置；它们属于服务器档案的一部分。

## 失败条件 / 反目标

- 切换一个新连接的服务器导致其他已建立或正在建立的连接改用新服务器。
- 用户选择服务器后、连接失败或取消后留下错误的设备偏好。
- 编辑服务器档案后，已有会话的连接上下文被追溯改变。
- 文件传输、终端等从同一设备打开的连接使用与主连接不同的服务器档案。
- 删除服务器档案后仍把设备路由到已删除或空的配置。
- 桌面功能改动意外改变移动端或 Web 的编译/运行路径。

## 用户体验

### 服务器管理

在桌面端“设置 → 网络”中，把当前单一的“ID/Relay Server”配置入口扩展为服务器档案管理：

- 列出所有档案，显示档案名称和主要 ID Server 地址。
- 添加档案时填写名称、ID Server、Relay Server、API Server、Key，并复用现有服务器校验逻辑。
- 编辑已有档案时修改同一组字段；引用该档案的设备偏好通过稳定档案 ID继续指向它，因此自动使用新配置。
- 可将一个档案设为全局默认；全局默认存储为档案的稳定 ID，而不是复制配置字段。
- 可删除档案。删除被设备偏好的档案时，清理这些设备的偏好，使它们回退到全局默认档案。
- 不允许删除最后一个档案；如果要删除当前默认档案，必须先把另一个档案设为默认，或由实现提供等价的安全回退流程。

服务器档案名称是 UI 展示字段，稳定内部 ID 不因重命名改变。第一版可以采用本地持久化 JSON/选项存储，但具体存储键和序列化格式由实现阶段结合现有配置 API 决定；应保留向后兼容和校验失败回退能力。

### 新建连接

桌面主连接页在远程 ID 输入区域增加服务器下拉选择：

- 下拉项显示档案名称，当前选择清晰可见。
- 输入或选择远程 ID 后，先查找该 ID 的已保存服务器档案 ID。
- 若偏好不存在、档案已被删除或档案数据无效，选择全局默认档案。
- 用户改变下拉选择只改变当前新建连接的连接上下文，不立即持久化。
- 从当前连接页发起远程桌面、文件传输、终端、端口转发、RDP 或查看摄像头时，复用相同的连接上下文；不能让这些功能重新按全局默认选择。
- 在会话完成认证并收到远程设备信息后，按纯远程 ID保存当前档案 ID；底层传输层的 `connection_ready` 仍只负责连接状态展示。保存动作应幂等，并且只能发生在成功连接事件之后。
- 重连属于已建立会话的生命周期，继续使用该会话原先的服务器上下文；不要因为全局默认或下拉框后来变化而重路由该会话。

现有外部 URI/命令行连接和 `id@server` 语法保持原路径。显式 `id@server` 优先于下拉框选择，并且该连接成功后不覆盖纯 ID 的服务器档案偏好；旧语法仍按原有 `other_server` 语义处理。由于本设计只覆盖桌面 UI，移动/Web 调用保持现状。

未指定档案的连接、服务启动、服务器测试、API/account 等仍由迁移后的全局默认档案驱动；编辑全局默认档案等价于修改这些既有全局行为。选择非默认档案只对当前新建会话生效，不改变全局默认或其他会话。

## 技术设计方向

### 当前代码边界

- 桌面网络设置入口：`flutter/lib/desktop/pages/desktop_setting_page.dart` 的 `_Network`。
- 现有服务器表单和 `ServerConfig`：`flutter/lib/mobile/widgets/dialog.dart` 与 `flutter/lib/common.dart`。
- 桌面连接页：`flutter/lib/desktop/pages/connection_page.dart`；移动端连接页不纳入本次修改。
- 连接分发：`flutter/lib/common.dart` 的 `connect`、`connectMainDesktop`，以及多窗口参数传递。
- 会话创建：`flutter/lib/models/model.dart` 的 `FFI.start` 和 `bind.sessionAddSync`。
- Native FFI：`src/flutter_ffi.rs` 的 `session_add_sync`，再到 `src/flutter.rs::session_add`。
- rendezvous/relay 选择：`src/client.rs` 的连接启动路径，以及 `src/rendezvous_mediator.rs` 的 relay 选择路径。
- 连接成功事件：`src/flutter.rs::FlutterHandler::set_connection_type` 发出 `connection_ready`，Dart 在 `flutter/lib/models/model.dart` 处理。
- 设备配置：已有 `PeerConfig.options` 和 `mainGetPeerOption` / `mainSetPeerOption`，但新增的服务器档案和全局档案列表不应复制到每个设备配置中。

### 服务器档案和偏好

需要引入两个层次的数据：

1. **本机服务器档案集合**：包含稳定档案 ID、名称和完整 `ServerConfig` 字段；另有全局默认档案 ID。
2. **设备偏好**：每个远程 ID只保存服务器档案 ID，复用 PeerConfig 的设备级持久化能力。

档案集合可以通过现有本机选项机制持久化为一个版本化 JSON；数据结构、键名、ID生成方式和迁移代码由实现计划确定。读取时应处理旧版本、坏 JSON、重复 ID、缺失默认项和引用不存在档案等情况，选择确定性的安全回退。

首次读取新结构时：

- 从既有全局 `custom-rendezvous-server`、`relay-server`、`api-server`、`key` 构建一个名为“默认服务器”的档案。
- 将其设为全局默认。
- 迁移应只执行一次，并避免在已有新结构时重复创建。
- 旧字段在迁移后是否继续作为兼容镜像由实现决定，但不能让旧字段覆盖用户后来对档案的编辑。

### 连接上下文

服务器档案选择不能通过修改全局 `Config` 实现。实现需要把当前档案的完整连接数据（至少 rendezvous/ID server、relay server、key，以及连接流程需要的 API server 信息）作为会话上下文传入 Native Rust，并在会话创建时固定下来。

实现阶段必须检查并覆盖：

- Flutter 多窗口从主页面到主窗口连接调用的参数序列化。
- 所有会调用 `FFI.start` 的桌面连接类型。
- `session_add_sync` 到 `LoginConfigHandler::initialize` 的参数链。
- `client.rs` 读取默认 `Config::get_rendezvous_server()` 和 relay 配置的路径。
- `id@server` 的 `other_server` 语义，避免新档案上下文与旧的显式服务器语法冲突。
- 连接上下文在 `Session`、`LoginConfigHandler`、重连和 relay fallback 中的生命周期。
- 仅在会话真正发出 `connection_ready` 后保存设备偏好。可由 Dart 处理该事件并调用设备选项写入，也可由 Rust 事件携带足够信息后处理；选择应避免多窗口重复保存和保存到错误的 ID。

已有会话的上下文必须是快照或等价的不可被全局设置回写的状态。服务器档案编辑只影响后续会话。

### 连接类型一致性

从主连接页发起的所有桌面连接类型要携带同一个服务器档案选择。打开文件传输、终端、端口转发等独立窗口时，现有窗口参数需要增加该上下文；若连接已经存在并只是把 tab 移到新窗口，则复用已创建 Rust session，不重新选择档案。
- 其他桌面端发起连接的入口（历史、收藏、设备卡片等）不增加服务器选择控件，但应按远程 ID读取有效的已保存档案偏好；没有偏好时使用全局默认。URI、命令行、移动端和 Web 仍走原有路径。
- 同一远程 ID同时有多个档案的连接时，以最后收到 `connection_ready` 的成功连接更新该 ID的偏好。重复成功事件保持幂等，不能写入不存在的档案。
- 删除档案只影响后续新建连接和设备偏好解析；已经创建的会话及其重连继续使用启动时捕获的连接上下文，即使该档案随后被删除或编辑。

## 验证要求

- 服务器档案迁移：旧单服务器配置首次启动后生成一个默认档案；再次读取不重复生成。
- 档案 CRUD：新增、编辑、重命名、设默认、删除及删除引用档案后的设备回退。
- 连接页选择：无设备偏好时使用全局默认；有有效偏好时使用偏好；偏好指向删除/坏档案时确定性回退。
- 失败不保存：连接取消、失败或在 `connection_ready` 前关闭，不改变设备偏好。
- 成功保存：收到 `connection_ready` 后仅保存对应远程 ID的当前档案 ID；重复事件不造成坏数据。
- 连接隔离：切换/编辑/删除档案不改变其他已建立会话的连接上下文；删除档案也不阻止已有会话重连。
- 连接类型：同一选择传递到远程桌面、文件传输、终端、端口转发、RDP 和查看摄像头；多窗口重用现有 session 时不丢失上下文。
- 其他桌面入口：历史、收藏、设备卡片等不提供额外选择控件，但读取同一设备偏好；URI、命令行、移动端和 Web 保持原路径。
- 显式服务器：`id@server` 优先于档案下拉选择，成功后不覆盖纯 ID 的档案偏好。
- 并发保存：同一远程 ID以最后收到的 `connection_ready` 为准，重复事件幂等且只写入仍存在的档案。
- 回归：移动端和 Web 不新增桌面专属依赖或破坏编译；旧的 `id@server` 连接路径保持可用。
- 遵循 `AGENTS.md`：Rust 测试放在邻近 `#[cfg(test)]` 模块，Flutter 测试放在 `flutter/test/*_test.dart`；不要生成或提交被忽略的 bridge 文件。

## 实现阶段留给构建者的决定

- 选择服务器档案 JSON 的具体字段、版本号、选项键和稳定 ID生成方式。
- 选择档案管理主要放在一个扩展对话框还是设置页内嵌列表，只要满足新增、编辑、删除、默认和校验行为。
- 选择连接上下文在 Rust/Dart 间传递的最小安全字段，以及成功事件保存偏好的责任边界。
- 复用现有 `ServerConfig` 校验、导入/导出能力，但不扩大第一版到移动端/Web。
- 采用最小必要改动，保留未启用新选择时的既有默认连接路径。
